Voici l'analyse détaillée des logs fournis, suivie des solutions concrètes pour résoudre ce problème de connectivité PostgreSQL dans votre pipeline CI/CD.

### 1. Analyse des Logs

| Horodatage | Niveau | Message | Interprétation |
| :--- | :--- | :--- | :--- |
| `10:32:11` | **ERROR** | `Connection refused: postgresql://localhost:5432/ai_platform` | **Erreur racine** : L'application tente de se connecter à PostgreSQL sur `localhost:5432`, mais aucune écoute n'est active sur ce port. Le service PostgreSQL n'est pas démarré ou n'est pas accessible à cette adresse. |
| `10:32:12` | **ERROR** | `Retrying... (1/3)` | Le mécanisme de retry est déclenché (logique correcte). |
| `10:32:15` | **ERROR** | `Retrying... (2/3)` | Deuxième tentative échouée. |
| `10:32:18` | **CRITICAL** | `Max retries exceeded. Pipeline aborted.` | **Échec final** : Après 3 tentatives, le pipeline s'arrête. |

#### 🔍 Causes Probables
1. **PostgreSQL non démarré** : Le conteneur ou le service PostgreSQL n'est pas lancé.
2. **Adresse IP incorrecte** : Dans un contexte Docker/CI, `localhost` pointe vers le conteneur lui-même, pas vers l'hôte ou un autre conteneur. Il faut utiliser le nom du service Docker (ex: `postgres`) ou l'IP de l'hôte.
3. **Port non exposé** : Le port 5432 n'est pas mappé ou ouvert.
4. **Service de dépendance manquant** : Dans GitLab CI, si PostgreSQL est un service, il doit être déclaré dans le `.gitlab-ci.yml`.

### 2. Solutions Proposées

#### ✅ Solution 1 : Corriger la configuration dans GitLab CI (Cas le plus probable)

Si vous utilisez **GitLab CI/CD**, vous devez déclarer PostgreSQL comme **service** et utiliser le nom du service dans la chaîne de connexion, pas `localhost`.

##### 📄 Exemple de `.gitlab-ci.yml` corrigé :

```yaml
stages:
  - test
  - deploy

# Service PostgreSQL pour tous les jobs qui en ont besoin
services:
  - postgres:15-alpine

variables:
  POSTGRES_USER: ai_user
  POSTGRES_PASSWORD: ai_password
  POSTGRES_DB: ai_platform
  # IMPORTANT : Utiliser le nom du service Docker, pas localhost
  DATABASE_URL: postgresql://ai_user:ai_password@postgres:5432/ai_platform

test_job:
  stage: test
  image: python:3.11-slim
  script:
    - echo "Connexion à PostgreSQL via le service 'postgres'"
    # Attendre que PostgreSQL soit prêt (important !)
    - python -c "import time; time.sleep(5)"
    - pip install -r requirements.txt
    - pytest
  dependencies: []
```

> ⚠️ **Point clé** : Remplacez `localhost` par `postgres` (le nom du service) dans `DATABASE_URL`.
