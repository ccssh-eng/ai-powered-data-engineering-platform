Voici un Dockerfile optimisé, sécurisé et prêt pour la production pour une API Flask avec MongoDB.

### 📄 `Dockerfile`

```dockerfile
# ==============================================================================
# Étape 1 : Installation des dépendances (Builder)
# ==============================================================================
FROM python:3.11-slim AS builder

# Désactiver la génération de .pyc pour réduire la taille et éviter les conflits
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

# Installer les dépendances système nécessaires pour la compilation (si requises)
# et les outils de build
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc \
    libpq-dev \
    && rm -rf /var/lib/apt/lists/*

# Créer un répertoire de travail
WORKDIR /app

# Copier uniquement les fichiers de dépendances pour exploiter la cache Docker
COPY requirements.txt .

# Installer les dépendances Python dans un environnement virtuel
# (Bonne pratique pour isoler les dépendances)
RUN python -m venv /opt/venv && \
    /opt/venv/bin/pip install --upgrade pip && \
    /opt/venv/bin/pip install --no-cache-dir -r requirements.txt

# ==============================================================================
# Étape 2 : Image de production finale
# ==============================================================================
FROM python:3.11-slim AS production

# Variables d'environnement de production
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PATH="/opt/venv/bin:$PATH"

# Créer un utilisateur non-root pour la sécurité
RUN addgroup --system appgroup && \
    adduser --system --ingroup appgroup appuser

# Changer le propriétaire du répertoire de travail
WORKDIR /app
RUN chown -R appuser:appgroup /app

# Copier l'environnement virtuel depuis l'étape builder
COPY --from=builder /opt/venv /opt/venv

# Copier le code de l'application
COPY --chown=appuser:appgroup . .

# Changer l'utilisateur courant pour exécuter l'application en non-root
USER appuser

# Exposition du port (à adapter selon votre configuration Gunicorn)
EXPOSE 8000

# Commande de démarrage
# Utilise Gunicorn pour la production (plus stable que le serveur Flask intégré)
# --workers : nombre de workers (à ajuster selon la charge)
# --bind : adresse et port d'écoute
CMD ["gunicorn", "--workers", "4", "--bind", "0.0.0.0:8000", "app:app"]
```

### 📄 `requirements.txt` (exemple)

```txt
Flask==3.0.0
pymongo==4.6.1
gunicorn==21.2.0
```

### 📄 `app.py` (exemple minimal)

```python
from flask import Flask
from pymongo import MongoClient

app = Flask(__name__)

# Connexion à MongoDB (l'adresse est passée via variable d'environnement)
client = MongoClient("mongodb://mongo:27017/")
db = client["myapp"]

@app.route("/")
def index():
    return {"message": "API Flask en production", "status": "OK"}

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8000)
```

### ✅ Points clés de sécurité et d'optimisation

1. **Multi-stage build** :
   - L'étape `builder` installe les dépendances avec les outils de compilation (`gcc`).
   - L'étape `production` ne contient que l'environnement virtuel et le code, sans les outils de build. Cela réduit significativement la taille de l'image finale.

2. **Utilisateur non-root** :
   - Création d'un utilisateur `appuser` avec le groupe `appgroup`.
   - L'application s'exécute avec cet utilisateur, limitant les dégâts en cas de compromission.

3. **Variables d'environnement** :
   - `PYTHONDONTWRITEBYTECODE=1` : Évite la génération de fichiers `.pyc`.
   - `PYTHONUNBUFFERED=1` : Permet un affichage immédiat des logs (utile pour le débogage).

4. **Gunicorn** :
   - Le serveur Flask intégré n'est pas conçu pour la production. Gunicorn est un serveur WSGI robuste et performant.

5. **Cache Docker** :
   - `requirements.txt` est copié avant le code, ce qui permet de réutiliser la cache des dépendances si le code change mais pas les dépendances.

### 🚀 Utilisation

Pour construire et lancer l'image :

```bash
# Construire l'image
docker build -t flask-mongo-api .

# Lancer le conteneur (avec MongoDB en local ou via un service)
docker run -d \
  --name flask-api \
  -p 8000:8000 \
  -e MONGO_URI="mongodb://localhost:27017" \
  flask-mongo-api
```

### 📝 Notes supplémentaires

- **MongoDB** : Assurez-vous que MongoDB est accessible depuis le conteneur. Vous pouvez soit :
  - Lancer MongoDB dans un autre conteneur et les connecter via un réseau Docker.
  - Utiliser une instance MongoDB externe (Atlas, etc.).
- **Variables d'environnement** : Passez les configurations sensibles (comme l'URI de MongoDB) via des variables d'environnement ou un fichier `.env` (ne jamais les hardcoder dans le Dockerfile).
- **Healthcheck** : Vous pouvez ajouter un `HEALTHCHECK` dans le Dockerfile pour vérifier la disponibilité de l'API.
